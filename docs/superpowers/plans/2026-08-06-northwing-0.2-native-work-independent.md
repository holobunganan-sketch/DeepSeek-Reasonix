# Northwing 0.2 Native Work and Independent Updates Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship Northwing 0.2.0 with Work represented as a native enhanced project session, a unified Reasonix-derived user experience, an isolated Northwing release/update channel, safe in-app replacement updates, and automatic migration of existing Work data.

**Architecture:** Keep the frozen Reasonix execution kernel for sessions, Goal, Delivery, tools, approvals, recovery, providers, and context management. Move Work identity and summaries into the native session/project-tree model, expose Work details through a lightweight session header and native drawer, and retain `.northwing/project.json` only for Work policy and artifact metadata. Replace inherited Reasonix distribution/update paths with a Northwing-only manifest, helper, installer, and release workflow.

**Tech Stack:** Go, React, TypeScript, Wails v2, NSIS, PowerShell, GitHub Actions, Node/tsx contract tests.

## Global Constraints

- Deliver all user-visible changes in one Northwing 0.2.0 release; do not publish an intermediate application version.
- Work is a native enhanced project session, not a detached product surface or second agent runtime.
- Preserve existing Reasonix session, Goal, Delivery, provider, model, tool, approval, checkpoint, and recovery behavior.
- Preserve and migrate Northwing 0.1.x Work and artifact data without destructive rewrites.
- Northwing must check and install only Northwing releases; Reasonix releases must never reach users.
- Windows updates must close the running app safely before replacing `northwing.exe` and must not offer an Ignore path for the main executable.
- Release artifacts, executable metadata, CLI output, update manifest, About UI, and installer metadata must all report 0.2.0.
