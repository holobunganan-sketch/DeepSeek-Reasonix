# Northwing 0.3.1 Stability Recovery Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Recover the complete Northwing 0.3 desktop surface, prove production wiring, and make the stable release fail closed unless Windows payloads are signed and clean.

**Architecture:** `NorthwingShell` owns product navigation and native window chrome. Existing Reasonix/Wails services remain authoritative for sessions, providers, settings, workspaces, project discovery, and file actions. A dependency-injected bridge boundary supports behavior tests while production uses the same `src/main.tsx` bootstrap.

**Tech Stack:** Go 1.26, Wails v2.12, React 19, TypeScript 6, pnpm, Playwright, PowerShell, NSIS, Windows Authenticode, Microsoft Defender CLI, GitHub Actions.

## Global Constraints

- Product version is exactly `0.3.1`; the existing resolver remains the single authority.
- Windows default viewport is 1240×720; minimum viewport is 760×480.
- Stable artifacts require valid signatures on `northwing.exe`, `northwing-update-helper.exe`, and setup.exe.
- Unsigned outputs are named `UNSIGNED-TEST-ONLY` and cannot reach the stable release job.
- No Defender exclusions, security-policy changes, packers, obfuscators, UPX, hidden shell cleanup, or swallowed production errors.
- Every production behavior change starts with a failing behavior test and ends with focused plus adjacent regression tests.
- Commits remain phase-scoped and never include unrelated Reasonix refactors.
