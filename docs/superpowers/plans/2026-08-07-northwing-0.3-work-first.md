# Northwing 0.3 Work-first Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a reviewable Northwing 0.3.0 branch and PR that makes Work the product entry point, gives Work a native persisted session identity, migrates 0.2 data safely, introduces Harness v3, and fails closed for unsigned Windows releases and updates.

**Architecture:** Persist `sessionKind/workId` in the existing session sidecar and project it through the current kernel APIs. Place a lazy Northwing product shell above the existing session workspace, adapt runtime evidence into Work projections, and retain the kernel as the sole execution authority. Formal Windows release uses one protected certificate credential for Authenticode and detached manifest signing.

**Tech Stack:** Go 1.26.5, React 19, TypeScript 6, Wails v2.12, Zustand, Vite 8, Playwright Chromium, Node/tsx, PowerShell, NSIS, Windows SignTool, GitHub Actions.

## Global Constraints

- Product version is `0.3.0`; formal tag is `northwing-v0.3.0` only after merge and every release gate.
- Work is the primary product entry. Quick Chat is secondary.
- The existing Reasonix-derived kernel remains the only planner, executor, agent loop, tool runtime, permission engine, checkpoint engine, and recovery engine.
- `northwing-v0.1.0` and `northwing-v0.2.0` directories remain byte-untouched.
- Existing 0.2 Work IDs, transcripts, artifact hashes and versions, final selection, model binding, quality, source policy, and Office interoperability remain intact.
- Ordinary user-visible DOM uses Northwing. Reasonix appears only in About, licenses, third-party attribution, and developer documentation.
- Work progress comes from Goal, canonical todos, tool events, approvals, asks, complete_step, and turn lifecycle. Timers never advance stage.
- Home does not load Work workspace, artifact preview, Office preview, terminal, Git diff, settings, Skills, MCP, Automation, or developer tool modules.
- Pull requests may produce unsigned test packages. Formal release publication requires verified SHA-256 Authenticode, RFC3161 timestamps, a signed update manifest, and `signtool verify /pa /all`.
- Normal update and installer paths contain no forced process termination.
- Every task starts with a failing assertion, ends with targeted verification, and lands as a reviewable commit.
