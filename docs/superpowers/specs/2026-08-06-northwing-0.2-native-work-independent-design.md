# Northwing 0.2 Native Work and Independent Updates Design

## Product boundary

Northwing is an independent product built from a frozen Reasonix kernel baseline. The kernel remains responsible for sessions, Goal, Delivery, models, tools, approvals, checkpoints, and recovery. Northwing owns product identity, Work session metadata, artifacts, UI integration, release assets, update discovery, and replacement installation.

Reasonix upstream changes are never merged or distributed automatically. Any future upstream intake is a deliberate, reviewed, tested Northwing change.

## Native Work session

A Work is a normal project topic/session with `sessionKind = work` and a compact Work summary. It appears in the same project tree, opens in the same tab and conversation surface, and uses the same runtime status. Work policy, acceptance state, artifact metadata, and final-version selection remain in `.northwing/project.json` and are linked to the native topic/session.

The detached Work toolbar is removed. The project create action offers Chat, Work, and Add project folder. Work rows reuse the native tree visuals and behavior. The active Work exposes a lightweight context header and a right-side drawer for overview, artifacts, history, and final selection.

## Persistence and migration

The current manifest is migrated idempotently. Before the first schema rewrite, Northwing creates `.northwing/project.v1.backup.json`. Existing Work records retain IDs, Goal/topic/session links, model/effort, quality/source policy, artifacts, hashes, history, and final selection. If safe migration fails, Northwing leaves the original file untouched and loads legacy data read-only.

## Updates and Windows installation

Northwing checks only a Northwing stable update manifest. Downloaded assets are verified before execution. A dedicated update helper receives a staged installer, requests a normal application shutdown, waits for `northwing.exe` to exit, runs the installer silently, validates the installed version, and restarts Northwing.

The installer detects a running Northwing instance and blocks replacement until it exits. The main executable cannot be skipped through Ignore. Failed replacement preserves the previous executable and reports a recoverable error.

## Release

Northwing release workflows build only Northwing-named artifacts and publish a Northwing update manifest. Inherited Reasonix release/update paths are excluded from product CI and guarded by source contracts. The one-step release target is `northwing-v0.2.0` after the complete PR is merged and the merge commit passes all required checks.
